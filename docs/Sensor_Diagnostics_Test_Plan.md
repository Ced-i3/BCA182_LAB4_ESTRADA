# Sensor diagnostics: planned hardware test

No modified firmware has been flashed or tested as of this document. Obtain explicit approval before uploading. Use COM4 at 115200 8N1. Logs report uptime (`t_ms`), sensor-task interval (`dt_ms`), uncalibrated acceleration in g and angular rate in degrees/second, AP3216C approximate illuminance and raw proximity, and task stack high-water marks in 32-bit words plus heap bytes. Tick timestamps are not wall-clock time. First interval includes startup; normal intended period is 500 ms. Serial reporting may miss button presses shorter than one sensor period: hold each button for at least one second.

1. Record initialization, WHO_AM_I and any NACK/timeout/configuration or overflow errors. `0xAF` corresponds to ICM20608-G and `0xAE` to ICM20608-D; a matching ID supports identification, not calibration or sensor performance. AP3216C does not have a unique ID in the reviewed register table; an ACK alone is insufficient.
2. Place the board stationary on a stable surface. Record several readings and verify the acceleration magnitude is roughly 1 g and gyro rates are near zero, within bias and noise. Do not infer alignment from axes without observation.
3. Tilt the board through distinct orientations, pausing each time; record how acceleration changes with gravity. Rotate the board gently around different axes; observe gyro response during motion and return toward zero at rest. Move it safely without pulling cables; record changes and any timing errors.
4. Change light on the optical sensor and place/remove a nearby object. Record approximate lux and proximity counts, not a distance. IR overflow marks proximity invalid. Allow for sensor conversion and ambient conditions.
5. Hold UP, DOWN, LEFT and RIGHT individually for at least one second; check each corresponding serial flag and the visible LED response. Record exact observations rather than assuming GPIO polarity.
6. Observe `dt_ms`, free/minimum heap, and each task's stack margin over sustained operation and fault conditions. Safe fault tests depend on board access; never disconnect powered components or short pins. Review missing samples, timing variation and errors before considering acquisition reliable.

The software bus is single-owner and clock-stretch waits are bounded, but does not implement nine-clock bus recovery. Sensor conversion latency, absolute physical sample rate, timing under load, register coherence and scale accuracy require physical verification. Software polling and serial output do not guarantee deterministic data-ready sampling.

References: [ICM-20608-G product specification](https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/ds-000081-v1.01.pdf), [RT-Thread board BSP](https://github.com/RT-Thread/rt-thread/blob/master/bsp/stm32/stm32f407-rt-spark/board/Kconfig), [AP3216C register map](https://shop.aftabrayaneh.com/image/data/product%20extension/AP3216-Module/AP3216-Module.pdf).
